Unterrichtskonzept

PhaseWas passiert?
1. MissionEin Minecraft-Bauproblem wird gestellt.
2. BlocklyDie Kinder lösen es mit visuellen Blöcken.
3. VorschauDas Ergebnis wird sofort im 3D-Viewer geprüft.
4. JavaScript-BrückeDer erzeugte JavaScript-Code wird mit den Blöcken verglichen.
5. ChallengeDie Kinder verändern oder erweitern das Bauwerk selbstständig.
6. MinecraftDas fertige JavaScript wird heruntergeladen und mit JSMN ausgeführt.

Empfohlene Progression

Lektionen 1–3: fast ausschließlich Blockly. 4–7: Blockly plus kurze Blicke auf den erzeugten Code. 8–12: Die Kinder sollen zunehmend erklären können, welcher JavaScript-Code hinter ihren Blöcken steckt.

Besonders wertvoll: Die 3D-Vorschau macht Debugging sichtbar. Ein Fehler ist nicht nur eine rote Meldung – häufig steht ein Bauteil einfach am falschen Ort. Daraus kann man sehr gut Fragen zu Programmzustand und Reihenfolge entwickeln.

Installation im Repository

Der Kurs wird von der Workshop-Homepage ausgeliefert (Repo javascriptMinecraftWorkshopServer), die JSMN IDE separat vom Repo webscriptcraft:

homepage/html/
  index.html      (Workshop-Startseite)
  kurs/
    index.html
    assets/style.css
    lektionen/...

Da Kurs und IDE auf unterschiedlichen Hosts laufen, wird der IDE-Link auf jeder Kursseite beim Container-Start per envsubst aus der IDE_URL-Umgebungsvariable gesetzt (siehe homepage/entrypoint.sh).
