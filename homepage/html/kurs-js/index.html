Didaktischer Aufbau

Jede Einheit folgt demselben Muster:

  1. Mission: Ein sichtbares Minecraft-Problem wird gestellt.
  2. Naive Lösung: Die Kinder lösen es zunächst mit dem bisher Bekannten.
  3. Problem: Die Grenzen dieser Lösung werden sichtbar.
  4. Neues Werkzeug: Ein JavaScript-Konzept wird eingeführt.
  5. Challenge: Die Kinder wenden es in einer eigenen Variante an.

Empfohlener Ablauf pro Einheit

PhaseDauerInhalt
Start5–10 minMission zeigen, Ergebnis in Minecraft demonstrieren
Gemeinsam15–20 minStartcode schreiben und schrittweise verändern
Üben20–30 minKleine Aufgaben und Varianten
Challenge15–25 minEigene Lösung bauen
Galerie5–10 minScripts gegenseitig ausprobieren und kurz vorstellen
Tipp: Gerade bei jüngeren Kindern lohnt es sich, zuerst das gewünschte Bauwerk zu zeigen. Danach entsteht die Frage „Wie kann ich das mit weniger Code bauen?“ fast von selbst.

Technische Nutzung mit script4kids / JSMN

Die Beispiele verwenden die vorhandenen Objekte player und drone. Typische Methoden im Kurs sind:

  • player.sendMessage(...)
  • player.getName(), player.getHealth()
  • drone.box(...), drone.box0(...)
  • drone.fwd(...), right(...), up(...) usw.
  • drone.chkpt(...) und drone.move(...)
  • drone.sphere(...), sphere0(...), maze(...), rainbow(...), castle(...)

Relative Pfade

Die Website benötigt keine feste Domain. Die Startseite lädt ihre CSS-Datei mit:

<link rel="stylesheet" href="assets/style.css">

Kapitel-Seiten laden dieselbe Datei eine Ebene höher:

<link rel="stylesheet" href="../assets/style.css">

Du kannst den gesamten Ordner also unter beliebigem Namen auf einen Webserver kopieren.
