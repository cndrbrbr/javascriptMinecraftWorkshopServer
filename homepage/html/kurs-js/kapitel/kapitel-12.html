Lernziel
Die Kinder wenden die gelernten Konzepte selbstständig in einem größeren Projekt an.

Jetzt gibt es keine vollständige Vorlage mehr. Jedes Team plant und programmiert einen eigenen Stadtteil.

Für Lehrkräfte: Erst die Aufgabe zeigen, dann das Problem gemeinsam besprechen und danach das neue JavaScript-Konzept einführen. So entsteht die Syntax aus einem sichtbaren Bauproblem.

Startcode

// Beispiel: Start eines eigenen Stadtprojekts
player.sendMessage("Wir bauen jetzt unseren Stadtteil!");

drone.chkpt("start");

// Ab hier kommen eure eigenen Funktionen:
// function haus(...) { ... }
// function laterne(...) { ... }
// function park(...) { ... }

Schritt für Schritt

1. Team wählen

Wohngebiet, Hochhäuser, Park, Schule, Bahnhof, Schloss oder Freizeitpark.

2. Anforderungen erfüllen

Verwendet Funktionen, Schleifen, Bedingungen und Checkpoints.

3. Testen und präsentieren

Führt das Script vor und erklärt, welche Programmierideen darin stecken.

Challenge:

Euer Stadtteil braucht mindestens 5 Gebäude oder Bauobjekte, eine selbst geschriebene Funktion, eine Schleife, eine if-Bedingung und einen Checkpoint. Bonus: verwendet `sphere0`, `maze`, `rainbow` oder `castle`.

Musterlösung

Die Musterlösung ist nur eine mögliche Lösung. Andere funktionierende Lösungen sind ausdrücklich erwünscht.

// Es gibt absichtlich keine einzige Musterlösung.
// Eine mögliche Idee:

function baum() {
    drone.box("OAK_LOG", 1, 4, 1);
    drone.up(4).sphere("OAK_LEAVES", 2);
    drone.down(4);
}

drone.chkpt("park");

drone.box("GRASS_BLOCK", 20, 1, 20);
drone.up(1);

for (var i = 0; i < 6; i++) {
    baum();
    drone.right(3);
}

drone.move("park").fwd(8).right(8).up(1);

if (player.getHealth() < 10) {
    player.sendMessage("Erst stärken, dann weiterbauen!");
} else {
    drone.sphere0("GLASS", 5);
    player.sendMessage("Der Glaspavillon ist fertig!");
}
Typische Fehler
  • Nicht alles auf einmal schreiben – Funktionen einzeln testen.
  • Bei Fehlern die letzte Änderung zurücknehmen und kleine Teile prüfen.
  • Ein funktionierendes kleines Projekt ist besser als ein riesiges, das nicht läuft.
